防抖 / 节流

同一串触发同时喂给三个函数：防抖等你停下来才执行，立即执行版在一轮开头执行，节流按固定间隔执行。在触发区里快速点或来回划，看四条轨道的差别。

  • 灰色短条就是 clearTimeout：每来一次新触发，防抖都会取消上一个定时器、重新计时，所以连续触发时 fn 一直不执行。
    •

  • 把 delay 调大再试：防抖需要你停得更久，节流执行得更稀。

    异步并发数限制
    
        
    默认是经典题：四个任务耗时 1000 / 500 / 300 / 400ms，最多同时跑 2 个。看每个 worker 一空下来就从队列领取下一个任务，以及完成顺序为什么是 2 3 1 4。

    • 500ms 时任务 2 完成：worker 2 立刻领取任务 3。800ms 时任务 3 完成，它再领取任务 4。任务 1 要到 1000ms 才结束。
      • 
        
    • 完成顺序是 2 3 1 4，results 仍是 [1000, 500, 300, 400]：因为结果按下标 i 存放。

    call / bind
    
        
    call 的本质是把函数临时挂到对象上，以方法的形式调用一次；bind 返回一个新函数，被 new 调用时，绑定的 this 会失效。
    
      
    
      
    
        
    
          
    
          
    
        
    
        
    
          
    
            
    
              
              
            
    
          
    
          
    
          
    
          
    
            
            
            
            
            
            
          
    
        
    
      
    
      
      
        
    • this 由调用方式决定：ctx[key]() 是方法调用，所以函数里的 this 就是 ctx。
      • 
        
    • Symbol 键 + try/finally：不会覆盖 ctx 原有的属性，函数抛错也能把临时属性删干净。apply 只是把数组展开后交给 call。
      • 
        
    • bound 靠 this instanceof bound 判断自己是不是被 new 调用：这要求 bound.prototype 继承自 fn.prototype。

    手写 new
    
        
    new 做了四件事：创建对象、连上原型、以它为 this 执行构造函数、决定返回谁。切换构造函数的 return，看最后的 p 到底是谁。
    
      
    
      
    
        
    
        
    
          
    
            
    
              
              
              
            
    
          
    
          
    
          
    
          
    
            
            
            
            
            
            
          
    
        
    
      
    
      
      
        
    • Object.create(Ctor.prototype) 一步做了两件事：创建对象，并把它的原型指向 Ctor.prototype。p.sayHi() 能调用，靠的就是这条原型链。
      • 
        
    • return 基本类型会被忽略，return 对象会顶替掉 obj：判断时要排除 null（typeof null === 'object'），函数也算对象。
      • 
        
    • 箭头函数不能被 new：它没有 prototype，第一行检查就会拦下它。

    继承：三种写法对比
    
        
    同一段场景：设置 Dog 的原型，new 两只狗，给 d1 的 tags 加一项，再调用 d1.sayName()。切换写法，看原型链怎么接起来、Animal 被执行了几次、tags 会不会被共享。

    • Animal.call(this, name) 负责实例属性：每 new 一只狗执行一次，name、tags 写在狗自己身上，互不影响。

    函数柯里化：闭包一层层记住参数
    
        
    sum3 = curry((a, b, c) => a + b + c)。参数没凑够 3 个，就返回一个新函数，它用闭包记住到目前为止的参数；凑够了才执行。最后一个例子是共用一个数组的错误写法，看它在复用时怎么出错。
    
      
    
      
    
        
    
          
    
          
    
        
    
        
    
          
    
            
    
              
              
              
              
            
    
          
    
          
    正在执行
    
          
    
            
    这一次收集到的参数（fn.length = 3）
    
            
    
          
    
          
    闭包里记住的参数
    
          
    
          
    
            
            
            
            
            
            
          
    
        
    
      
    
      
      
        
    • 每次参数不够，就返回一个新函数：它用闭包记住到目前为止收到的参数，下一次调用时接着收。
      • 
        
    • 拼参数用 [...args, ...rest] 生成新数组：旧闭包里的数组从来不会被改，所以 add10 能反复使用。
      • 
        
    • 判断的是收集到的总数：args.length >= fn.length，一次传几个都行；共用一个数组的写法，会把上一次的参数带进下一次。
